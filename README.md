House Price Prediction Pipeline

| | Deskripsi |
| ----------- | ----------- |
| Dataset | Dataset yang digunakan bersumber dari Kaggle [House Price Prediction](https://www.kaggle.com/datasets/debayank2024/house-price-prediction) yang memuat transaksi historis penjualan properti di Washington State dengan total **4.600 baris data** tanpa *missing values*. Data dibagi otomatis oleh `CsvExampleGen` menjadi **3.081 baris Train** (~67%) dan **1.519 baris Eval** (~33%). Dari 18 atribut mentah, sebanyak **15 atribut** dimasukkan ke pipeline TFX (3 kolom non-esensial/kebocoran data dieliminasi: `date`, `street`, dan `price_per_sqft`), yang terdiri dari:<br>- **1 Target Numerik (Float):** `price` (rentang $0 hingga $26.600.000).<br>- **12 Fitur Numerik:** `bathrooms` (float), `bedrooms` (float), `condition` (int), `floors` (float), `sqft_above` (int), `sqft_basement` (int), `sqft_living` (int), `sqft_lot` (int), `view` (int), `waterfront` (int), `yr_built` (int), dan `yr_renovated` (int).<br>- **2 Fitur Kategorikal (String/Teks):** `city` (44 kota unik) dan `statezip` (77 kode pos unik). |
| Masalah | Prediksi harga properti/rumah memiliki variansi nilai yang sangat tinggi dengan rentang fitur fisik dan lokasi geografis yang heterogen. Diperlukan sistem machine learning terautomasi end-to-end yang menjamin validasi anomali data otomatis, rekayasa fitur bebas *training-serving skew*, pemilihan hyperparameter optimal, serta pipeline deployment yang reliabel. |
| Solusi machine learning | Membangun pipeline Machine Learning end-to-end menggunakan TensorFlow Extended (TFX) dengan orchestrator **Apache Beam (`BeamDagRunner`)**. Pipeline mengintegrasikan 10 komponen terstruktur: `CsvExampleGen`, `StatisticsGen`, `SchemaGen`, `ExampleValidator`, `Transform`, `Tuner` (KerasTuner), `Trainer` (`tf_keras`), `Resolver` (`LatestBlessedModelStrategy`), `Evaluator` (TFMA), hingga `Pusher` ke TensorFlow Serving berbasis kontainer Docker. |
| Metode pengolahan | **1. Pembagian Data:** Data dibagi otomatis oleh `CsvExampleGen` dengan rasio 2:1 menjadi partisi **Train (3.081 baris / ~66,98%)** dan partisi **Eval (1.519 baris / ~33,02%)**.<br><br>**2. Rekayasa Fitur & Alasan:**<br>- *Z-score standardization* (`tft.scale_to_z_score`): Diterapkan pada 12 fitur numerik karena rentang skala antarfitur sangat timpang (misal: `sqft_lot` mencapai ratusan ribu vs `floors` bernilai satuan). Standarisasi ke rata-rata 0 dan variansi 1 mempercepat serta menstabilkan konvergensi gradient descent.<br>- *Vocabulary indexing* (`tft.compute_and_apply_vocabulary`): Diterapkan pada 2 fitur kategorikal (`city` dan `statezip`) untuk memetakan string ke indeks integer diskret, diikuti *index clipping* ke rentang `[0, 149]` guna menangani nilai Out-of-Vocabulary (indeks -1) agar tidak menyebabkan *runtime error*.<br><br>**3. Hermetic Preprocessing Graph:** Komponen `Transform` menghasilkan berkas *preprocessing graph* (`transform_graph`) yang menyatu secara hermetis (*hermetic*) ke dalam *serving signature* SavedModel. Seluruh transformasi inferensi dieksekusi oleh graph tersebut sehingga parameter pra-pemrosesan identik antara masa pelatihan dan produksi, mencegah terjadinya *Training-Serving Skew*. |
| Arsitektur model | **1. Konfigurasi Tuner:** Optimasi menggunakan KerasTuner RandomSearch (`max_trials=3`, `executions_per_trial=1`) dengan metrik optimasi meminimalkan `val_mean_absolute_error`. Search space yang dieksplorasi mencakup `units_1` (32–128), `dropout_rate` (0.1–0.4), `units_2` (16–64), dan `learning_rate` (1e-2, 1e-3, 5e-4).<br><br>**2. Best Hyperparameters (Hasil Tuner Terakhir):**<br>- `units_1`: 32<br>- `dropout_rate`: 0.2<br>- `units_2`: 32<br>- `learning_rate`: 0.01 (1e-2)<br><br>**3. Topologi Model:** Arsitektur Deep Neural Network multi-input berbasis `tf_keras`. Sebanyak 12 fitur numerik yang telah distandarisasi dan 2 fitur kategorikal (yang dipetakan melalui layer Embedding dimensi 8 lalu di-flatten) digabungkan menggunakan layer `Concatenate`. Output gabungan diteruskan ke Dense Layer 1 (32 unit, aktivasi ReLU), Dropout Layer (rate 0.2), Dense Layer 2 (32 unit, aktivasi ReLU), dan diakhiri Dense Layer tunggal (1 unit, aktivasi Linear) untuk regresi harga. Model dikompilasi menggunakan optimizer Adam (learning rate 0.01) dan loss function Mean Squared Error (MSE). |
| Metrik evaluasi | Evaluasi performa model diuji secara komprehensif menggunakan TensorFlow Model Analysis (TFMA) dengan metrik Mean Absolute Error (MAE) dan Mean Squared Error (MSE). Komponen `Evaluator` menetapkan kriteria **Threshold Blessing** berupa batas atas nilai MSE (`upper_bound = 1e14`). Model baru dinyatakan **BLESSED** hanya jika nilai MSE pada data evaluasi berada di bawah $1 \times 10^{14}$ dan performanya tidak mengalami degradasi dibanding baseline terdahulu dari `LatestBlessedModelStrategy`. |
| Performa model | **1. Konfigurasi Pelatihan Trainer:**<br>Model dilatih menggunakan komponen Trainer TFX yang diorkestrasi oleh Apache Beam dengan konfigurasi `train_steps=100` dan `eval_steps=50`, mengadopsi kombinasi hyperparameter terbaik dari komponen Tuner (`units_1`: 32, `dropout_rate`: 0.2, `units_2`: 32, `learning_rate`: 0.01).<br><br>**2. Hasil Evaluasi Komponen Evaluator (TFMA pada Data Validasi):**<br>- Mean Absolute Error (MAE): 129.800,7031 ($1,298007 \times 10^5$)<br>- Mean Squared Error (MSE): 150.468.000.000,00 ($1,504680 \times 10^{11}$)<br>- Status Validasi: **BLESSED** (Nilai MSE TFMA sebesar $1,504680 \times 10^{11}$ berada jauh di bawah ambang batas atas / threshold upper bound $1 \times 10^{14}$ sehingga model dinyatakan valid dan disetujui untuk diekspor oleh Pusher ke direktori serving).<br><br>**3. Interpretasi Hasil:**<br>Penerapan hyperparameter optimal dari KerasTuner memberikan performa yang sangat baik dengan penurunan MAE hingga ~129.800 pada sebaran data evaluasi. Preprocessing hermetis dari TensorFlow Transform menjamin tidak terjadi *training-serving skew* saat model memproses inferensi di production.<br><br>**4. Rencana Peningkatan ke Depan:**<br>- Mengeliminasi baris transaksi properti berharga $0 pada tahap awal pembersihan data.<br>- Menerapkan transformasi logaritmik (log1p) pada label target price.<br>- Menambah ruang pencarian tuning dan memperdalam arsitektur layer.<br>- Melakukan feature crossing pada fitur lokasi geografis (city dan statezip). |
| Opsi deployment | Model hasil pelatihan diekspor ke dalam format SavedModel lengkap dengan *preprocessing graph* hermetis dari TensorFlow Transform. Sistem disajikan menggunakan image resmi **TensorFlow Serving (`tensorflow/serving:latest`)** yang dikemas ke dalam **Docker Container** dengan konfigurasi `prometheus.config`. Kontainer dideploy ke platform **Heroku Container Registry (PaaS)** yang menjalankan service pada web dyno dan menangani routing port dinamis serta terminasi enkripsi HTTPS publik. |
| Web app | [house-pricing-model](https://erlanggajuni45-house-pricing-022d6b7408cd.herokuapp.com/v1/models/house_pricing_model/metadata) |
| Monitoring | Observabilitas sistem model serving diimplementasikan menggunakan kombinasi **Prometheus** dan **Grafana**:<br><br>**1. Konfigurasi Prometheus:**<br>- Melakukan scraping metrik internal TensorFlow Serving secara otomatis tiap **5 detik** (`scrape_interval: 5s` sesuai berkas `monitoring/prometheus.yml`) melalui endpoint HTTPS `/monitoring/prometheus/metrics` pada host Heroku (`erlanggajuni45-house-pricing-022d6b7408cd.herokuapp.com`).<br>- Metrik utama yang dipantau meliputi throughput inferensi (`:tensorflow:serving:request_count`) dan eksekusi graph Keras (`:tensorflow:core:graph_runs`).<br><br>**2. Hasil Monitoring Pengujian Riil:**<br>- **Total Request Count:** Tercatat sebanyak **12 request inferensi berhasil** dengan rincian label `{model_name="house_pricing_model", status="OK"}` bernilai **12**, serta ditemukan request gagal (`status="NOT_FOUND"` = 1).<br>- **Graph Runs:** Tercatat sebanyak **9 kali pemanggilan graph core** (`:tensorflow:core:graph_runs` bernilai **9**) saat pemrosesan batch data dari notebook pengujian `erlanggajuni45-testing.ipynb`.<br>- **Visualisasi Grafana:** Panel metrik pada `erlanggajuni45-grafana-dashboard.png` menampilkan grafik berundak (*stepwise increase*) yang responsif mengikuti penambahan request inferensi secara real-time tanpa lonjakan latensi atau kegagalan koneksi. |
